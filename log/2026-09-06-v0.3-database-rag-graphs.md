# Deep Funding V0.3: Private Database, Public Knowledge and Persistent Agent Runs

Started: 2026-09-06, Asia/Shanghai.

V0.3 is the point where DeepFunding moves from the V0.2 local-first / browser-oriented matching experience into a persistent data-backed Agent system with inspectable private records, public funding/compliance knowledge, saved match results and reproducible Agent execution history.

## Product direction behind V0.3

The product requirement was to make the information entered by both sides of the funding marketplace persist beyond one browser session and become reusable by Agents.

The intended operating model is:

```text
Founder / Company / Enterprise
        ↓
structured private profile + funding need
        ↓
DeepFunding persistent backend
        ↓
Information Agent
        ↓
Analysis Agent
        ↓
Audit Agent
        ↓
Match Agent
        ↓
Funding-side profiles / preferences / public evidence
        ↓
Saved matches + human-reviewable result
```

On the funding side, the same infrastructure stores provider profiles and funding preferences so the marketplace can become genuinely bidirectional rather than a one-off founder questionnaire.

The long-term product model can later add hosted accounts, subscriptions, entitlement enforcement and Agent/API access. V0.3 deliberately stores only lightweight subscription metadata; it does **not** claim production billing, hosted multi-tenant authentication or live entitlement enforcement.

## What changed from V0.2 to V0.3

### 1. Persistent private backend

V0.3 adds a Python backend using SQLite + SQLAlchemy together with FastAPI CRUD / OpenAPI endpoints.

Persistent model families cover:

- Founder profiles.
- Company profiles.
- Funding-provider profiles.
- Funding preferences.
- Funding needs.
- Saved matches.
- Input snapshots.
- Agent run history.
- Audit records.
- Lightweight subscription metadata.
- Public-source / knowledge snapshots.

The key architectural change is that matching is no longer limited to transient frontend state. Stored ORM rows feed the matching service, and the resulting Match, four AgentRun records and AuditRecord are persisted.

### 2. Private Data Explorer

A private local Data Explorer was added so a human can inspect and edit the stored system state through forms, tables, filtering, sorting, pagination and JSON detail views.

This is important because DeepFunding is intended to become an Agent-to-Agent system, but the underlying inputs and decisions must remain inspectable rather than becoming an opaque autonomous process.

### 3. Four-stage Agent execution history

V0.3 persists the four logical stages of an Agent run:

```text
Information Agent
Analysis Agent
Audit Agent
Match Agent
```

A run can therefore be reconstructed from its stored inputs and retrieved evidence instead of only showing a final score.

### 4. Funding RAG Graph

A public funding knowledge layer was added with sourced Shenzhen-oriented institutional and program references.

The initial public corpus contains 18 dated references and classification / template structures. Its purpose is source-backed retrieval and reasoning support, **not** a claim that every referenced funding program is currently open or that every amount is verified.

Primary government and institutional sources take precedence over guessed terms. Unknown values remain unknown.

### 5. Compliance RAG Graph

A separate compliance knowledge graph was added so the Agent can distinguish evidence types such as:

- reporting,
- company response,
- allegations,
- analysis,
- disputed claims.

A related controversy is not automatically converted into a confirmed compliance violation. Human review remains explicit where evidence is disputed or incomplete.

### 6. Matching + evidence persistence

Both public knowledge graphs feed Agent output. Stored retrieval arrays retain source URLs and content hashes so the evidence used by a run can be inspected later.

This makes the V0.3 matching flow closer to:

```text
Private profile
+ Private preference / need
+ Public funding evidence
+ Public compliance evidence
        ↓
Inspectable Agent reasoning
        ↓
Saved match
        ↓
Human review / introduction decision
```

rather than a single ephemeral similarity score.

### 7. Subscription metadata foundation

V0.3 adds lightweight subscription metadata as a future-facing data primitive. The purpose is to support a later model where registered Agents or users can receive controlled access to private data, matching or API capabilities.

Not implemented in V0.3:

- payment processing,
- billing,
- hosted multi-tenant accounts,
- entitlement enforcement,
- private cross-device synchronization,
- automatic external introductions.

These remain future work and require separate security / product gates.

## Preserved from V0.2

V0.3 does not replace the V0.2 product surface. It preserves:

- React / Worker / D1 sandbox.
- Eight original Agent contracts.
- Capital/resource catalogue and taxonomy.
- Founder and Funding RSI.
- Shared TypeScript RSI engine.
- Browser experience.
- CLI and TUI.
- Public/private deployment boundary.

The local private SQLite database does **not** deploy to Cloudflare.

## Failure learned during V0.3

An immediate server termination after a successful match response exposed a commit-after-response race.

Fix:

- use FastAPI function-scoped database dependencies,
- complete the commit before returning success,
- verify persistence with two independent real Uvicorn processes.

The regression test now checks company, match and Agent-run persistence after restart.

CI also caught a security test that implicitly depended on an existing frontend build. Private file paths now consistently return 404 regardless of build state, and generated JSON uses LF line endings across platforms.

## Performance measurement

For one fixed synthetic company/provider pair on Windows / Python 3.11.3, with 5 warmups + 25 measured transactions, including SQL reads, retrieval, Match / four AgentRun / AuditRecord writes and commit:

- median: 5.9397 ms
- p95: 6.6422 ms

HTTP, browser and network time are excluded.

This is an engineering latency measurement, **not** an accuracy benchmark and not a speed comparison against V0.2.

Runtime LLM calls/tokens = 0 for this deterministic release path.

Real-world funding performance, retrieval precision, match calibration, credit/investment quality and downstream introduction success remain **UNMEASURED**.

## V0.3 release principle

> **Private data + public evidence + inspectable reasoning.**

Unknown is not zero. Missing evidence is not approval. A related controversy is not a guilt finding. Agent output must remain reconstructable and human-reviewable.
